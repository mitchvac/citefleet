# Shopify

- **Market share:** 5.4% of all websites (W3Techs, 2026-09-11)
- **Category:** SaaS site builder
- **File access:** admin UI only (theme code editor + Admin API); no filesystem, no SFTP/SSH
- **Automatable by the CiteFleet script (rclone):** no — rclone cannot reach a Shopify
  store. Automatable by a Shopify app using the **Admin GraphQL API**
  (`themeFilesUpsert`, `urlRedirectCreate`); see "Automation" below.

## Where the web root is

There is no web root. Shopify serves the storefront from its own infrastructure;
the merchant never gets a directory. The only paths at the site root that a
merchant can control are the ones Shopify has defined a **theme template** for.
As of 2026-09-11 those are:

| Root path | Theme template that renders it |
|---|---|
| `/robots.txt` | `templates/robots.txt.liquid` |
| `/llms.txt` | `templates/llms.txt.liquid` |
| `/llms-full.txt` | `templates/llms-full.txt.liquid` |
| `/agents.md` | `templates/agents.md.liquid` |
| `/sitemap.xml` | none — Shopify-generated, not overridable |

Every other root path (`/anything.txt`, `/.well-known/*`) returns the storefront
404 page. Merchant-uploaded files from **Content → Files** are served under
`/cdn/shop/files/…` on the store's own domain, **not** at the root.

## Steps to install the five files

### 1. `robots.txt` — yes, fully editable

1. Shopify admin → **Online Store** → next to the theme, the **…** menu → **Edit code**.
2. In the **Templates** folder, click **Add a new template**, select **robots**,
   click **Create template**. This creates `templates/robots.txt.liquid`.
3. Keep the default Liquid that iterates `robots.default_groups` (so Shopify's own
   rules keep updating), then append the CiteFleet directives and the `Sitemap:`
   lines.

Creating this template **replaces** Shopify's generated `/robots.txt` output —
Shopify's wording is that the template "renders the `robots.txt` file". It is not
a merge. The `robots.default_groups` Liquid object is how you get Shopify's
maintained rules back into your replacement; Shopify explicitly warns against
"replacing the entire template with plain text" because "default rules are updated
regularly to ensure that SEO best practices are always applied."

Shopify names the supported edits as: allow/disallow URLs, crawl-delay rules,
**add extra sitemap URLs**, and block crawlers. Shopify classes the whole thing as
an "unsupported customization" that Shopify Support will not help with.

### 2. `sitemap.xml` — cannot be replaced; declare an extra one instead

`/sitemap.xml` is generated by Shopify and updated automatically when products,
collections, pages, images or blog posts change. There is **no** documented way to
edit it, replace it, or add a second sitemap file at the root.

The workaround is the supported one: add a `Sitemap:` line to
`robots.txt.liquid` pointing at a CiteFleet-hosted sitemap. Shopify lists "Add
extra sitemap URLs" as an intended use of the template, so this is on the
supported path, not a hack.

### 3. `llms.txt` — yes, natively, since 2026-05-28

Shopify shipped native agent-discovery templates on 2026-05-28. Every store
already serves `/agents.md`, and `/llms.txt` and `/llms-full.txt` mirror it by
default. To take control of `/llms.txt`:

1. **Online Store → Themes → Edit code**.
2. Right-click the **Templates** folder → **New File** → name it `llms.txt.liquid`.

Lookup order for `/llms.txt` is: `llms.txt.liquid` → `agents.md.liquid` →
Shopify-generated default. A custom `llms.txt.liquid` affects **only** `/llms.txt`;
`/agents.md` and `/llms-full.txt` are unaffected unless you add their own templates.

Constraints from the docs: it must be `llms.txt.liquid` (a JSON template is not
allowed), content is "standard text or Markdown and Liquid", and the Liquid context
is reduced — only the `request` and `agents` objects are injected, **not** `shop`,
`collections`, `articles` etc. A static CiteFleet `llms.txt` pasted in verbatim is
therefore fine; anything that wanted to enumerate products from Liquid is not.

### 4. `.well-known/botcentral.txt` — not possible. Use DNS TXT.

No theme template exists for any `.well-known/` path and there is no file-upload
feature that publishes to the site root. Shopify does generate some `.well-known`
files itself — "This generates two `.well-known` JSON files on your custom domain:
`apple-app-site-association` for iOS, `assetlinks.json` for Android", configured at
**Shopify admin → Apps and integrations → App settings → API Integrations →
Storefront API integration → Configure** — but that mechanism writes Shopify's own
JSON payloads for app-domain verification from identifiers you supply. It is not a
general "put a file here" facility, and the filenames are fixed.

**This is not a blocker.** Use the apex DNS TXT record instead, which BotCentral
scores higher anyway. If the domain is Shopify-managed: **Settings → Domains** →
the domain → **DNS settings** → **Add custom record** → TXT. If the domain is
third-party, add the TXT at the registrar.

### 5. IndexNow key file — not possible at the root

`<key>.txt` at the root would 404. Three partial routes, none of them clean:

- **`keyLocation`.** IndexNow permits the key file off-root if you pass
  `keyLocation`, but then "a key file at `http://example.com/catalog/key12457EDd.txt`
  can only validate URLs beginning with `http://example.com/catalog/`". On Shopify
  the only writable same-host location is `/cdn/shop/files/…`, so the key would only
  authorise submitting `/cdn/shop/files/*` URLs — useless for product and collection
  pages. Dead end.
- **URL redirect.** **Content → Menus → View URL Redirects → Create URL redirect**,
  from `/<key>.txt` to an externally hosted key file. Redirects only fire on paths
  that already 404, and `/<key>.txt` does 404, so the redirect would be created and
  would fire. Whether IndexNow follows a cross-host redirect when fetching the key
  file is **UNVERIFIED** — indexnow.org's documentation does not address redirect
  handling (searched: indexnow.org/documentation). Do not promise this works.
- **Apps.** Several App Store apps submit to IndexNow via the API on the merchant's
  behalf, sidestepping the key file. Not an official Shopify feature; not verified here.

## The `.well-known/` problem

Moot for CiteFleet. There is no mechanism and no workaround, but the apex DNS TXT
record proves the same thing and scores higher. Tell the merchant to skip the file.

## Gotchas

- **The robots template replaces, it does not merge.** A merchant who pastes plain
  text into `robots.txt.liquid` silently loses every rule Shopify maintains — and
  Shopify's own warning is that "incorrect use of the feature can result in loss of
  all traffic." Always emit `robots.default_groups` first.
- **Shopify claimed `/llms.txt` platform-wide.** Stores that previously served an
  `llms.txt` via a proxy, redirect or app were overridden when the native route
  shipped. Any CiteFleet integration must go through `templates/llms.txt.liquid`,
  not a redirect, or it will be shadowed by Shopify's route.
- **Reduced Liquid context in `llms.txt.liquid`** — `shop`, `collections`,
  `articles` and the other global objects are not available. Liquid that works in a
  normal template will render empty here.
- **Themes are versioned.** Editing code on the live theme is immediate, but
  publishing a different theme, or a theme update from the vendor, drops any
  template that theme does not carry. The robots/llms templates live **in the
  theme**, so they must be re-added after every theme swap.
- **URL redirects only fire on 404s.** Reserved prefixes `/apps`, `/application`,
  `/cart`, `/carts`, `/orders`, `/services`, `/shop` cannot be redirected at all,
  and neither can fixed paths like `/products` and `/collections`.
- **Trial plans restrict file uploads** to JS, CSS, GIF, JPEG, PNG, JSON, CSV, PDF,
  WebP and HEIC — `.txt` is not on that list. Paid plans allow "any file type except
  HTML". Irrelevant to the root files but relevant if anyone tries the `/cdn` route.
- **Private/password-protected stores** make the sitemap inaccessible.

## If files cannot be placed

Achievable natively: `robots.txt` and `llms.txt` — both fully, both via theme
templates. `sitemap.xml` is replaced by a `Sitemap:` declaration in `robots.txt`
pointing at a CiteFleet-hosted sitemap. `.well-known/botcentral.txt` → apex DNS TXT
record. IndexNow key file → no supported mechanism; either skip IndexNow or use an
app that submits over the API.

## Automation

Shopify has a public Admin API that covers everything above except the sitemap:

- **`themeFilesUpsert`** (GraphQL Admin) — "Creates or updates theme files in an
  online store theme", up to 50 files per request. Inputs: `themeId` (ID!) and
  `files[]` of `{ filename, body: { type: TEXT|BASE64|URL, value } }`. Writing
  `templates/robots.txt.liquid` and `templates/llms.txt.liquid` is exactly this
  call. Scope: `write_themes`.
  **Caveat:** Shopify requires apps to hold an **exemption** to modify theme files —
  an approval request submitted to Shopify. A CiteFleet app cannot write theme files
  without it. This is the single biggest obstacle to automating Shopify.
- **`urlRedirectCreate`** (GraphQL Admin) — inputs `path` and `target`; scope
  `write_online_store_navigation`. Whether `target` may be a full external URL is
  not stated in the API reference (**UNVERIFIED** at the API level), though the
  merchant-facing help doc says the destination "can be a relative URL … or a full
  URL, such as `http://www.example.com/collection/shirts`".
- **Sitemap:** no API. Generated only.
